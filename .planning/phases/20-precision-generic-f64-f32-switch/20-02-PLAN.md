<objective>
Wave 1 (shared math leaves, group A): genericize the small/medium `#[cube]` math modules — Boys function, Obara-Saika recurrence, primitive-pair data, and STG math — over `F: Float` (device) / `F: CintFloat` (host wrappers). `boys.rs` is the reference refactor whose shape every other file copies. Const tables stay `[f64; N]` (FROZEN values) and are injected as `F` at the host/launcher boundary.

Purpose: These are the leaf functions the per-family kernel launchers (Wave 2 plans) call. Genericizing them first, with `<f64>` threaded at the call boundary, keeps the f64 path green while preparing the chain for f32 monomorphization. (`rys.rs` — 1,140 f64-lines — is genericized separately in Plan 03 to stay within context budget.)

Output: Four genericized math modules with their f64 monomorphization byte-identical to today, host wrappers bound on `CintFloat`, and a new `boys_gamma_inc_host::<f32>()` smoke test proving the f32 host path produces finite non-zero values.
</objective>

From cintx-core (Plan 01): `pub trait CintFloat: ... + num_traits::Float + num_traits::FromPrimitive + sealed::Sealed { fn from_f64_lossy(x: f64) -> Self; }` and `pub enum PrecisionKind { F64, F32 }`. Device `#[cube]` fns bound `F: cubecl::prelude::Float`; host wrappers bound `F: CintFloat`.

Current boys.rs reference shape (the analog every math file copies):
- boys.rs:25-26  `pub const SQRTPIE4: f64 = 0.886226925452758...;` and `pub const TURNOVER_POINT: [f64; 40] = [...];` — KEEP as f64; inject as `F` at boundary.
- boys.rs:86     `pub fn boys_gamma_inc_host(t: f64, m: u32) -> Vec<f64>` → `boys_gamma_inc_host<F: CintFloat>(t: F, m: u32) -> Vec<F>`; `let turnover = F::from_f64_lossy(TURNOVER_POINT[m as usize]);`
- boys.rs:150-153 `pub fn erf_host(x: f64) -> f64 { unsafe extern "C" { fn erf(x: f64) -> f64; } ... }` — FROZEN f64 libm linkage; for F path wrap `F::from_f64_lossy(erf_host(x.to_f64().unwrap()))`.
- boys.rs:173    `#[cube] pub fn boys_gamma_inc(f: &mut Array<f64>, t: f64, m: u32, turnover: f64)` → `<F: Float>(f: &mut Array<F>, t: F, m: u32, turnover: F, sqrtpie4: F)`.

Intrinsic substitution map (verified for f32+f64 in cubecl-core 0.10.0): `f64::exp→F::exp`, `f64::sqrt→F::sqrt`, `f64::erf→F::erf` (or `boys_erf_approx::<F>`), natural log → `F::ln` (NOT `F::log`, that is 2-arg — Phase 19 D-02). `Array<f64>→Array<F>` indexed `[k as usize]`. Small exact literal `0.5f64 → F::new(0.5)`; precision-critical const → passed `F` param.

CubeCL form to preserve: loop counters `u32`; function-call syntax `F::exp(x)` not `.exp()`; `Array` indexed via `as usize`. CubeCL prelude shadows host f64 methods inside `#[cfg(test)]` — use precomputed reference literals in tests (Pitfall 2 / Phase 19 D-02).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| const f64 math tables ↔ generic `F` injection | Internal numeric conversion at the host/launcher boundary; risk is correctness (f64-path precision regression), not external attack. |
| `#[cube]` generic body ↔ CubeCL expansion | Device-code generation; risk is a wrong intrinsic name silently degrading results, not a security surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-04 | Tampering | `F::new(literal)` on a precision-critical const (SQRTPIE4) | mitigate | Precision-critical constants are passed as `F` params injected via `from_f64_lossy` (full f64 precision on the f64 path), never `F::new(f64_literal)` which truncates to f32 (Pitfall 5); f64 byte-identity test guards regression. |
| T-20-05 | Tampering | wrong generic intrinsic (`F::log` vs `F::ln`) | mitigate | Substitution map mandates `F::ln` for natural log (Phase 19 D-02); f64 byte-identity tests catch any silent algorithm drift. |
| T-20-06 | Tampering | genericizing a FROZEN const/blob (TURNOVER_POINT, roots_xw .bin) | mitigate | Tables stay `[f64; N]`/binary blobs; serena symbol-scoped edits skip them; acceptance criteria assert they remain f64-typed. |
| T-20-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all deps already in Cargo.lock (RESEARCH §Package Legitimacy Audit). |

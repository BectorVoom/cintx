GAP 1 closure (PREC-02 / D-04 / ROADMAP SC-2): expose spinor/complex safe-API outputs as `num_complex::Complex<F>`. Today `IntegralTensor<F>` returns complex/spinor results as `owned_values: Vec<F>` with a `complex_interleaved: bool` flag (interleaved real/imag layout). That contradicts locked decision D-04 ("Spinor/complex outputs propagate as `Complex<F>` via num-complex") and ROADMAP Success Criterion 2 ("spinor/complex outputs propagate as `Complex<F>`"). The operator decision is IMPLEMENT — do NOT take the override/accept-deviation path.

Purpose: make the verification truth "PREC-02: spinor/complex outputs propagate as Complex<F>" literally TRUE. The typed `Complex<F>` view also strengthens the phase's type-safety thesis (the type system prevents a caller treating an f32 complex lane as f64 — the T-20 Tampering mitigation) and prevents a caller mis-reading an interleaved buffer as if it were real values.

Output: a `num-complex` direct dependency on cintx-rs, and a `Complex<F>` typed accessor/view on `IntegralTensor<F>` (and a convenience on `TypedEvaluationOutput<F>`) that reinterprets the contiguous interleaved `Vec<F>` into `&[Complex<F>]` for complex outputs. The existing `owned_values: Vec<F>` field and the real-valued (non-complex) path are unchanged.

        /// Complex view of the output for spinor/complex operators (D-04 / SC-2).
        ///
        /// Returns `Some(Vec<Complex<F>>)` when `complex_interleaved == true` (Spinor
        /// outputs): the contiguous interleaved `[re, im, re, im, ...]` `owned_values`
        /// buffer is reinterpreted element-for-element into `Complex<F>` (num_complex's

        /// outputs, where callers consume `owned_values: Vec<F>` directly.
        pub fn complex_values(&self) -> Option<Vec<num_complex::Complex<F>>> {
            if !self.complex_interleaved {
                return None;
            }
            // owned_values.len() is even for complex_interleaved (re/im pairs).
            debug_assert_eq!(self.owned_values.len() % 2, 0);
            Some(
                self.owned_values
                    .chunks_exact(2)
                    .map(|pair| num_complex::Complex::new(pair[0], pair[1]))
                    .collect(),
            )
        }
    }

<objective>
Wave 4 (safe API surface): make `SessionRequest::evaluate` a method-level generic `evaluate::<F: CintFloat>()` returning `TypedEvaluationOutput<F>` with `owned_values: Vec<F>`, while keeping `evaluate()` (unparameterized) byte-identical via the `F = f64` type default + delegation. This is the public-facing half of D-02/D-03/D-04: callers opt into f32 with `req.evaluate::<f32>()`; every existing call site compiles unchanged.

Purpose: The kernels (Plans 04/05) and the executor capability branch + precision plumbing (Plan 06) are precision-aware; this plan exposes the choice at the safe API. The output type is parameterized so the type system prevents a caller from confusing f32 and f64 results (the T-20 Tampering mitigation). The f64 path stays the default everywhere (D-12) and all existing oracle gates pass unchanged (PREC-04).

Output: a generic `evaluate::<F>()`, generic `TypedEvaluationOutput<F = f64>` / `IntegralTensor<F = f64>`, the staging buffer sized + reinterpreted for `F`, `ExecutionOptions.precision` set from `F`, and an `evaluate::<f32>()` smoke test returning `Vec<f32>`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-chosen `F` ↔ output type `TypedEvaluationOutput<F>` | The type parameter encodes the requested precision; risk is a caller treating f32 output as f64 — prevented by the type system (Vec<f32> ≠ Vec<f64>). |
| owned `Vec<F>` staging ↔ `&mut [f64]` ExecutionIo (frozen) | Internal bytemuck reinterpretation of a facade-owned buffer; risk is a mis-sized buffer (OOB), mitigated by sizing in `size_of::<F>()`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-19 | Tampering / Spoofing | f32 result silently consumed as f64 by a caller | mitigate | `evaluate::<f32>()` returns `TypedEvaluationOutput<f32>` (`owned_values: Vec<f32>`); the type system makes f32/f64 confusion a compile error (RESEARCH §Security Domain T-pattern 1). |
| T-20-20 | Elevation | facade staging buffer sized for f64 but reinterpreted as f32 (or vice-versa) | mitigate | Buffer sized in `size_of::<F>()`; bytemuck cast requires `F: Pod` (f32/f64 both Pod, proven in Plan 01); OOM-safe `try_reserve_exact` retained; the evaluate::<f32> smoke test + the f64 oracle gate bound both directions. |
| T-20-21 | Tampering | breaking an existing `req.evaluate()` call site (D-12 violation) | mitigate | The unparameterized `evaluate()` must resolve to f64 unchanged; the existing oracle parity tests (arity2/3/4) compile + pass at atol=1e-12 as the regression gate. |
| T-20-SC | Tampering | npm/pip/cargo installs | accept | At most `bytemuck = "1"` added to cintx-rs (already a workspace dep in cintx-cubecl, slopcheck-approved); no new external package (RESEARCH §Package Legitimacy Audit). |

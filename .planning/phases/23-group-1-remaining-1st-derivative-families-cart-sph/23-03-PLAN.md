<objective>
Register and implement `int3c2e_ip2` (DRV1-05): the first derivative of the 3-center-2-electron
integral with ∇ on the auxiliary `k` center. This is the ONE cluster-A family that is NOT a
mechanical clone of an existing nabla center, because of the slot-mapping landmine (RESEARCH
Pitfall 2 / PATTERNS center_3c2e.rs assignment):

**cintx's 3c2e g-tensor maps the real auxiliary `k` into the 2e `ll` slot** (the 2e `lk` slot is
a phantom s-function): `build_2e_shape(li+1, lj, 0, lk)` for int3c2e_ip1 (two_electron.rs:91-93,
real k in `ll`, bra raised). So the int3c2e_ip2 derivative on the real aux k must derive the
**`ll` slot**, requiring **`nabla1l_2e`** — added in plan 01. Build the g-tensor with the real-k
headroom in the `ll` slot: `build_2e_shape(li, lj, 0, lk+1)`, feed exponent `ak` (the real-k
exponent). gout authority: `CINTgout2e_int3c2e_ip2` (int3c2e.c:99), `G2E_D_K` on the auxiliary k,
3 components i-fastest. nroots = `(li + lj + (lk+1))/2 + 1`; max-l = d; fail-closed at nroots>5.

Clone `launch_center_3c2e_ip1` (center_3c2e.rs:1641) and its device kernel
`center_3c2e_ip1_kernel` (center_3c2e.rs:907); add the `"ip2"` operator branch after the existing
`"ip1"` branch (center_3c2e.rs:1906).

Purpose: Banks DRV1-05 and completes cluster A. This plan is sequenced AFTER plan 02 because it
appends to the same shared registration files (raw.rs, build.rs, vendor_ffi.rs, manifest lock) —
running it in a separate wave avoids merge conflicts on those append-only files. Output:
int3c2e_ip2 registered + a vendor parity test green at atol=1e-12.

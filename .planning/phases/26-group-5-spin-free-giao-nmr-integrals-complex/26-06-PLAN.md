<objective>
Close WR-01: GIAO/monolithic-complex families are unusable under memory-limit chunking.
`write_giao_complex_staging` and `launch_two_electron_giao2e` are MONOLITHIC whole-block
writers requiring the FULL `2 * real_total` staging; but the safe-API `evaluate` path
slices per-chunk staging via `staging_elements_for_chunk` (suffix - prefix), so any
memory_limit_bytes forcing chunk_count > 1 yields a per-chunk BufferTooSmall.

Purpose: `eval_raw` already handles this correctly (full-block `chunk_staging` of
`staging_elements` per chunk — raw.rs:1061-1070). The safe-API path must match, OR mark
these families non-chunkable so a splitting limit fails up front with a typed
MemoryLimitExceeded. This is an availability regression, not data corruption — but the
GIAO family is inoperable under chunking today.

Output: A fixed `evaluate` chunk-staging path + a runtime test asserting the intended
behavior under a small memory_limit_bytes.

This plan touches ONLY planner.rs — no overlap with the one_electron.rs work in 26-04/05/08.
</objective>

```rust
fn staging_elements_for_chunk(plan: &ExecutionPlan<'_>, chunk: &ChunkInfo) -> Result<usize, cintxRsError> {
    let total_units = plan.workspace.work_units.max(1);
    let start = chunk.work_unit_start.min(total_units);
    let end = chunk.work_unit_start.checked_add(chunk.work_unit_count)?.min(total_units);
    let prefix = plan.output_layout.staging_elements.saturating_mul(start) / total_units;
    let suffix = plan.output_layout.staging_elements.saturating_mul(end) / total_units;
    Ok(suffix.saturating_sub(prefix).max(1)) // <-- smaller than full block when chunk_count > 1
}
```

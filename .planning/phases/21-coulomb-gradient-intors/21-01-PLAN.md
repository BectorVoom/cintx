<objective>
Plumb the `PTR_RINV_ORIG` env slot (`env[4..6]`) end-to-end following the `f12_zeta` (env[9]) precedent: a typed `rinv_orig: Option<[f64; 3]>` field on `OperatorEnvParams`, a `validator.rs` gate that rejects an `iprinv` operator with no origin, a `raw.rs::eval_raw` read block that populates the field from the env array, and a `with_rinv_origin`-style setter on the safe-API options. This is the foundation Wave 2 (`int1e_iprinv`) and Wave 4 (`ECPscalar_iprinv`) consume.

Purpose: `int1e_iprinv` and `ECPscalar_iprinv` are per-atom Hellmann–Feynman / per-nucleus ECP forces evaluated at a single rinv origin. There is currently NO rinv-origin plumbing in cintx — `raw.rs:34` documents `PTR_RINV_ORIG = 4..6` in a comment but nothing reads it. Without this slot, an iprinv kernel has no origin to evaluate at and would silently produce wrong values. The validator gate makes "iprinv without an origin" a typed failure, not UB.

Output: `OperatorEnvParams.rinv_orig` field + `with_rinv_origin` setter (planner.rs); `validate_rinv_orig_env_params` (validator.rs); `PTR_RINV_ORIG: usize = 4` const + `eval_raw` read block + `is_iprinv_family_symbol` predicate (raw.rs); env round-trip + validator-rejection unit tests.
</objective>

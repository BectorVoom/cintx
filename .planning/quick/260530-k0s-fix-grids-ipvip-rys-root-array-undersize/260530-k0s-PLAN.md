<objective>
Fix the pre-existing grids host-fallback bug (todo grids-ipvip-rys-root-undersize-rocm): the host
contraction fns grids_contract_nuclear_like / _ip / _ipip / _ipvip compute the correct
`nrys_roots` (= (Σl)/2 + 1, up to 5) but fetch only TWO Rys roots via
`if nrys_roots == 1 { rys_root1_host } else { rys_root2_host }`, producing a 2-element u_arr/w_arr.
The `for n in 0..nrys_roots` loop then panics `index out of bounds: len 2 index 2` whenever the
device→host fallback fires for nroots>2 (li+lj high enough). `grids_contract_spvsp` delegates to
`grids_contract_ipvip`, so it is covered transitively. The device kernels intentionally wire only
rys_root{1,2} (GRIDS_MAX_DEVICE_NROOTS=2) and fall back to these host fns for nroots>2 — so the host
fns MUST supply nroots roots.

Fix: replace each 2-root if/else with the existing general dispatcher
`let (u_arr, w_arr) = rys_roots_host(nrys_roots as usize, x_boys);` (rys.rs:3235, dispatches
rys_root{1..5}_host, returns Vecs of length nroots; byte-identical to rys_root1/2_host for n<=2,
correct for 3..=5, fail-closed panic for >5 — the separate deferred Wheeler todo). Update the import
(add rys_roots_host; drop now-unused rys_root1_host/rys_root2_host). No #[cube] kernel changes (these
are plain host fns). Output: grids derivative host fallback correct for nroots up to 5.
</objective>

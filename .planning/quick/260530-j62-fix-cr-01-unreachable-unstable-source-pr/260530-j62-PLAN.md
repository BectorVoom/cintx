<objective>
Fix CR-01 (pre-existing, from commit 319d055): `validate_profile_and_source_gate` in
`crates/cintx-compat/src/raw.rs` has TWO `is_source_only()` blocks. The first (raw.rs:997-1007)
returns `Ok(())` early whenever the `unstable-source-api` feature is enabled, making the second
block's `is_compiled_in_profile("unstable-source")` membership check (raw.rs:1023) permanently
unreachable dead code — so a source-only operator not actually compiled into any available profile
is silently accepted instead of rejected.

CORRECTED DESIGN (do NOT apply the code-review's literal suggestion, which regresses two entries):
`active_manifest_profile()` only ever returns base/with-f12/with-4c1e/with-f12+with-4c1e — NEVER
"unstable-source". The manifest has TWO source-only `unstable::source::2e` entries compiled in BASE
profiles (`['base','with-f12','with-4c1e','with-f12+with-4c1e']`), plus the origi/grids/breit/origk/ssc
families compiled in `['unstable-source']`. So a source-only symbol is legitimately available iff it is
compiled into the ACTIVE profile OR the `unstable-source` profile. Checking ONLY "unstable-source"
(the dead block's literal logic) would wrongly reject the two base-profile source::2e symbols.

Fix: collapse to a single is_source_only() block — feature gate, then reject only when the symbol is
compiled in NEITHER the active profile NOR "unstable-source"; delete the dead duplicate block.
Output: a gate where the membership check is reachable and correct for all source-only entries.
</objective>

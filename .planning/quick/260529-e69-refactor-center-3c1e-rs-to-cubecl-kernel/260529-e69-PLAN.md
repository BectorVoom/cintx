## Goal

## Template (authoritative reference)

`center_2c2e.rs` is the exact pattern to follow:
- `#[cube(launch)] fn center_2c2e_kernel<F: Float + CubeElement>(...)` — single work item (`UNIT_POS == 0`), zeroes its output buffer in-kernel, runs the full VRR/contraction inline. **3c1e has NO Rys quadrature** — drop all `rys_root*`/`urys`/`wrys` machinery and port the 3c1e algorithm instead (combined j+k VRR → i-HRR → k-separation HRR → triple Cartesian contraction).
- `fn run_2c2e_device<R: Runtime>(client, ...) -> Vec<f64>` — generic-over-Runtime dispatcher; compute on-device at **f64**, create buffers via `client.create_from_slice(f64::as_bytes(..))`, launch `kernel::launch::<f64, R>(...)`, read back with `client.read_one_unchecked`. Name the 3c1e analog `run_3c1e_device`.
- `launch_center_2c2e_typed::<F: CintFloat>(backend, plan, spec, staging)` — the per-precision inner. Keep `launch_center_3c1e_typed` but route its numeric core through `run_3c1e_device` on the `match backend { Cpu | Wgpu | Cuda | Rocm | Metal }` arms (each `#[cfg(feature=...)]`-gated exactly as 2c2e does), then do the existing cart→sph copy / `F::from_f64_lossy` cast at the output stage.
- `launch_center_3c1e` outer precision dispatcher signature stays **byte-for-byte unchanged** (registered `FamilyLaunchFn`).

## Key 3c1e algorithm facts (preserve exactly — from current host code)

- 3 shells (i, j, k). G-tensor layout: `dli=li+1`, `dlj=lj+lk+1` (combined), `dlk=lk+1`; `g_stride_i=1`, `g_stride_j=dli`, `g_stride_k=dli*dlj`. Alloc `g_size = max(dli*dlj*dlk, dli*vrr_nmax)` where `vrr_nmax = li+lj+lk+1`. Flat layout `[gx | gy | gz]`, each `g_alloc` long.
- Per-primitive prefactor: `common_factor = SQRTPI * PI * fac_sp(li)*fac_sp(lj)*fac_sp(lk)`; screening `eijk=(ai*aj*rr_ij + ai*ak*rr_ik + aj*ak*rr_jk)/aijk`, skip if `> 60.0`; `dijk = exp(-eijk)/(aijk*sqrt(aijk))`; `fac = common_factor * dijk`. Base case `gx[0]=1, gy[0]=1, gz[0]=fac`.
- VRR (combined j+k, displacement `rjrijk[d] = rj[d] - (ai*ri+aj*rj+ak*rk)/aijk`, **negative sign** `disp=-rjrijk`): `g[dj]=disp*g[0]`; `g[(j+1)*dj]=aijk1*j*g[(j-1)*dj]+disp*g[j*dj]`, `aijk1=0.5/aijk`, `dj=dli`.
- i-HRR (`rirj = ri-rj`): for `i=1..=li`, `j=0..=nmax-i`: `g[i+j*dj]=g[i-1+(j+1)*dj]-rirj*g[i-1+j*dj]`.
- k-separation HRR (`rjrk=rj-rk`, `dk=dli*dlj`): for `k=1..=lk`, `j=0..=mmax-k`, `i=0..=li`: `g[base+i]=g[base+i+dj-dk]+rjrk*g[base+i-dk]`, `base=k*dk+j*dj`, `mmax=lj+lk`.
- Contraction: triple loop over `cart_comps(li) × cart_comps(lj) × cart_comps(lk)`; output `out[(k_idx*ncj + j_idx)*nci + i_idx] += gx*gy*gz` (i fastest, k slowest). Cartesian-component enumeration order must match the host `cart_comps` (lx desc, ly desc).
- Triple primitive loop order in the launcher: `kp` outer, then `jp`, then `ip`; contraction-coeff accumulation `ck,cj,ci`.

## CubeCL `#[cube]` authoring rules (from `docs/manual/Cubecl/*` — MANDATORY)

These are the pitfalls the manuals + `cubecl_error_solution_guide/` call out. The
2c2e template already obeys all of them; the 3c1e port must too:

1. **No plain-Rust fn calls inside `#[cube]`** (E0433 "not a crate or module"). Every callee must itself be `#[cube]` or be inlined. 3c1e has no Rys helper, so **inline the entire G-tensor fill + contraction** in the kernel body — do NOT call the host `fill_g_tensor_3c1e`/`contract_3c1e_ovlp`/`cart_comps`/`common_fac_sp` from inside the kernel.
2. **No `if`-as-expression returning a value** (E0308 `ExpandElementTyped` vs `{float}`). Use the statement form: `let mut d = xij; if axis == 1u32 { d = yij; } if axis == 2u32 { d = zij; }` (exactly the 2c2e idiom). Never `let d = if .. {..} else {..};`.
3. **Math via associated functions, not methods** (E0599 `__expand_*_method`). Use `F::exp(x)`, `F::sqrt(x)`, `F::cast_from(n)`, `F::new(lit)` — never `x.exp()` / `x.sqrt()`. (`common_factor` and the `exp(-eijk)`/`sqrt(aijk)` prefactor must use `F::exp` / `F::sqrt`.)
4. **Kernel-legal types only**: `F` floats and `u32`/`i32` for indices/counters. No `usize` locals, no `u64`, no `Vec`, no host `for`. Index arrays as `g[(expr) as usize]` (the `as usize` cast at the index site is fine, as 2c2e does).
5. **No `continue`/`break`** inside `#[cube]` `while` loops — they are not reliably lowered. For the exponent screen, do NOT `continue`; instead guard the primitive body: `if eijk <= expcutoff { ...fill+contract... }` and always advance the loop counter.
6. **`while` loops only** (manual counter `i += 1u32;`), single work item guarded by `if UNIT_POS == 0u32`. Reproduce `cart_comps` ordering inline with the descending nested-`while` idiom 2c2e uses (extended to 3 indices i/j/k, each tracking its own linear `*_idx`).
7. **Macro fan-out**: exactly ONE `#[cube(launch)]` entry (`center_3c1e_kernel`). No per-type or per-shape launch duplicates. Keep it generic `<F: Float + CubeElement>`; the host launcher picks `::launch::<f64, R>`. li/lj/lk/nprim*/nctr* are **runtime `u32` args** (2c2e passes li/lk as runtime u32 — only its Rys `nroots` is `#[comptime]`; 3c1e has no Rys, so it needs **no `#[comptime]` arg at all**).
8. Host buffers via `client.create_from_slice(f64::as_bytes(&v))`; read back via `client.read_one_unchecked`; launch with `CubeCount::Static(1,1,1)`, `CubeDim::new_1d(1)` — identical to `run_2c2e_device`.

## Precision policy (same as 2c2e)

Device compute runs at **f64** for both `PrecisionKind` variants; read-back buffer
is cast to `F` at the c2s / Cartesian output stage via `F::from_f64_lossy`. This
preserves the f32-parity contract. Keep the `WR-06` precision-aware nonzero
sentinel and `ExecutionStats` block verbatim.

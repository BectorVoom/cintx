# Quick Task 260529-r2g: Refactor center_2c2e to a CubeCL `#[cube]` kernel (generics float) + ROCm random oracle test

## Problem

`crates/cintx-cubecl/src/kernels/center_2c2e.rs` is the 2c2e (two-center
two-electron Coulomb) integral launcher. Today `launch_center_2c2e` does
`let _ = backend;` and runs the **entire** G-tensor fill + contraction
pipeline **host-side on the CPU in f64**, even when `CINTX_BACKEND=rocm`
resolves `ResolvedBackend::Rocm(client)`. No integral family currently
executes on the GPU (all are host-only; GPU conversion was deferred to v1.4).

## Goal

Refactor the numeric core into a real CubeCL `#[cube(launch)]` kernel
**generic over `F: Float`**, dispatched onto the resolved backend's
`ComputeClient` (CPU `CpuRuntime`, ROCm `HipRuntime`, …), with results read
back to the host. Then add + run a **random idempotency oracle test on the
ROCm backend** (gated like the existing rocm parity test).

## Locked decisions (from discussion)

- **Kernel scope:** Real device dispatch. Emit `#[cube(launch)]`, allocate
  device buffers, launch on the `ResolvedBackend` client, read back. The
  G-tensor fill + Cartesian contraction run on-device; `cart_to_sph` /
  spinor transforms stay host-side (their coefficient tables are host-only).
- **Oracle test:** Random idempotency on the ROCm backend — randomized shell
  pairs/exponents, run int2c2e on ROCm, assert self-consistency + non-zero.
  No vendor build required.

## Feasibility (verified up front)

- `cargo test -p cintx-oracle --features rocm --no-run` → exit 0 (cubecl-hip
  0.10 compiles against ROCm 7.1.1, gfx1152 / Radeon 860M).
- Throwaway smoke test launched `rys_root2::<f64>` on `HipRuntime` and read
  back correct roots `[0.0955…, 2.0317…]` — **f64 `#[cube]` execution works
  on gfx1152.**

## Precision contract (must preserve)

The current code keeps all intermediates in **f64** and only casts to `F` at
output (`F::from_f64_lossy`); the f32 parity gate (`f32_parity.rs`, family
`2c2e`) is calibrated against that. So: the kernel is genuinely generic over
`F: Float`, but the launcher runs it at **f64** on-device for both
`PrecisionKind` variants and casts the read-back buffer to `F` at the c2s/output
stage. This keeps both the f64 vendor gate (atol 1e-9) and the f32 gate green.

## Design

`center_2c2e_kernel<F: Float>` (`#[cube(launch)]`, single work item,
`UNIT_POS == 0`):
- `#[comptime] nroots: u32` — selects `rys_root{1..5}` via `comptime!` (avoids
  the documented runtime-nroots MLIR dispatch issue; no Rust monomorphization
  blow-up per the fan-out manual).
- runtime scalars: `li, lk, nprim_i, nprim_k, nctr_i, nctr_k: u32`;
  `rix..rkz: F`; `common_factor: F`; `pie4: F`.
- input arrays: `exps_i, exps_k, coeff_i, coeff_k: &Array<F>`.
- scratch arrays: `g: &mut Array<F>` (3·g_size), `urys, wrys: &mut Array<F>`
  (nroots).
- output: `cart_out: &mut Array<F>` (nci·nck), zeroed in-kernel, accumulated.

Body mirrors host `fill_g_tensor_2c2e` (base case, i-VRR, k-VRR, mixed i+k
cross term with `b00`) + the Cartesian contraction, in CubeCL-safe form
(statement-form `if`, `F::sqrt`/`F::exp`, `u32` counters, `as usize` only for
indexing, `F::cast_from`/`F::new` constants).

Launcher (`launch_center_2c2e_typed::<F: CintFloat>`, signature unchanged so
existing in-crate tests keep working):
1. Prep host data as f64 (coords, common_factor, flattened exps/coeffs, sizes,
   nroots).
2. Generic `run_2c2e_device::<R: Runtime>(client, …) -> Vec<f64>`: create
   buffers, `center_2c2e_kernel::launch::<f64, R>(…)`, `read_one_unchecked`.
3. `match backend { Cpu(c) => run::<CpuRuntime>, Rocm(c) => run::<HipRuntime>,
   Wgpu/Cuda/Metal => run::<…> }`.
4. c2s/spinor/cart on host with output cast to `F` (unchanged from today).

## Tasks

1. **Implement the kernel + device-dispatch launcher** in `center_2c2e.rs`.
   Keep `fill_g_tensor_2c2e` as a host reference used by the existing unit
   tests. Verify on CPU first.
2. **Add the ROCm random idempotency test** to
   `crates/cintx-oracle/tests/center_2c2e_parity.rs` (`#[cfg(feature="rocm")]`
   + `#[ignore]` + `CINTX_ROCM_ORACLE=1` gate), randomized inputs.

## Verification ladder

- `cargo test -p cintx-cubecl --features cpu` — in-crate dispatch unit tests
  (`test_2c2e_precision_dispatch_f64/f32_*`) now run through the device kernel
  on `CpuRuntime`.
- `cargo test -p cintx-oracle --features cpu --test center_2c2e_parity` —
  cpu idempotency.
- `CINTX_ORACLE_BUILD_VENDOR=1 cargo test … center_2c2e_parity` vendor parity
  (atol 1e-9) — **gold standard** the device kernel must still satisfy.
- `cargo run -p xtask -- rocm-oracle` (or the gated `cargo test --features
  rocm -- --ignored`) — the new random idempotency test on gfx1152.

## must_haves

- truths:
  - Under `CINTX_BACKEND=rocm`, the 2c2e G-tensor + contraction execute on the
    ROCm device (not host).
  - The kernel is generic over `F: Float`.
  - f64 vendor parity (atol 1e-9) still passes via the CPU `CpuRuntime` device path.
- artifacts:
  - `center_2c2e_kernel` `#[cube(launch)]` in `kernels/center_2c2e.rs`.
  - random rocm idempotency test in `center_2c2e_parity.rs`.

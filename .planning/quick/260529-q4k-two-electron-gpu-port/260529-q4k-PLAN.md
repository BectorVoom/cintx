<objective>
Refactor `crates/cintx-cubecl/src/kernels/two_electron.rs` so the SCALAR int2e
(four-center electron-repulsion) path runs a real CubeCL `#[cube(launch)]` device
kernel generic over `F: Float`, dispatched on the resolved backend (CPU / Wgpu /
Cuda / **ROCm/HIP** / Metal), then add and run a random-quartet oracle parity
test that exercises the ROCm backend and shows 0 divergence vs the vendored
libcint 6.1.3 oracle.

This is the FIFTH GPU family port, following the proven template established by
2c2e (`center_2c2e.rs`), 3c2e (`center_3c2e.rs`), ECP, and 1e: a `#[cube(launch)]`
kernel generic over `F`, with intermediate compute done in f64 on-device and the
output cast to `F`; `#[comptime] nroots` selecting `rys_root{1..5}` via
`comptime!` branches; a `run_<family>_device<R: Runtime>` dispatcher; and a host
`launch_*_typed<F>` that matches on `ResolvedBackend` and calls
`run_..._device::<cubecl_hip::HipRuntime>(client, ...)` for the
`ResolvedBackend::Rocm(client)` arm.

HOST/DEVICE SPLIT (honest, CLAUDE.md-compliant — mirrors 3c2e):
- ON DEVICE (the `#[cube(launch)]` kernel): the per-primitive-quartet G-tensor
  build (`fill_g_tensor_2e`: Rys roots/weights via `rys_root{1..5}`, the 2D VRR
  fill `vrr_fill_axis`, and the branch-specific 4D HRR transfer — all four
  branches `hrr_{lj2d,kj2d,il2d,ik2d}_4d`) PLUS the Cartesian contraction
  (`contract_2e_cart`), accumulated over all primitive and contraction quads into
  a per-(ci,cj,ck,cl) Cartesian block buffer.
- ON HOST (stays, like ECP's adaptive radial machinery and 2c2e/3c2e c2s): the
  `cart_to_sph_2e` / `cart_to_spinor_sf_4d` representation transforms (their
  coefficient tables are host-only) and the contraction-major AO scatter into
  `staging` via `F::from_f64_lossy`.

SCOPE DECISION (documented per domain guidance): THIS quick task ports ONLY the
SCALAR 2e path (`operator_name() != "ip1"`) to a device `#[cube(launch)]` kernel.
The `int2e_ip1` gradient path (`launch_two_electron_ip1`, which reuses f12.rs
`gout_ip1`/`nabla1i_2e` on the host) STAYS HOST in this task — it is already
covered by `two_electron_ip1_parity.rs` and is a larger, separable port. The
PRIMARY deliverable is: the scalar 2e path runs a real device kernel that
actually executes on the ROCm backend, validated at 0 divergence vs vendor.

Purpose: move the core 2e numeric work onto the CubeCL device backend per the
project's "CubeCL is the primary compute backend" constraint, completing the 2e
family's device port to match the 2c2e/3c2e/ecp/1e precedent.

- `crates/cintx-oracle/tests/two_electron_random_rocm_parity.rs`, a new randomized

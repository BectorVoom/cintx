<objective>
Port the four 1e GRADIENT operators (ipovlp, ipkin, ipnuc, iprinv) in
`crates/cintx-cubecl/src/kernels/one_electron.rs` from their current host-side
per-primitive pipeline (`contract_grad_1e_bra`, `contract_ipkin`,
`contract_nuclear_grad`) onto CubeCL `#[cube(launch)]` device kernels generic
over `F: Float`, then add and RUN a randomized ROCm oracle parity test covering
all four on the ROCm backend.

This closes the gap left by quick task 260529-imi, which ported only the scalar
1e operators (overlap/kinetic/nuclear) on-device and explicitly left the four
gradient operators host-side. The scalar device infrastructure already in the
file (`one_electron_scalar_kernel` #[cube(launch)] ~189, `run_1e_scalar_device`
~611, `run_1e_scalar_on_backend` ~734, device-vs-host cross-check tests ~2438) is
the in-file template; `center_3c2e.rs`'s `center_3c2e_ip1_kernel` dual-path
gradient port is the closest cross-file template (on-device nabla + 3-component
component-leading output + nroots>5 guard + spinor rejection + 5-arm dispatch).

Purpose: All 1e integral evaluation (scalar AND gradient) runs on the CubeCL
device backend per the CLAUDE.md architecture constraint (CubeCL primary; host
CPU limited to planning/validation/marshaling/transforms). No 1e operator
remains a host-CPU compute path.

Output: Device kernels for all four gradient operators, wired into the live
dispatch, byte/atol-preserving against the existing host parity tests, plus a
ROCm random oracle proving mismatch_count=0 on real AMD hardware.
</objective>
